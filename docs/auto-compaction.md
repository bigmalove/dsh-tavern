# 上下文压缩

默认使用手动压缩，不会自动压缩剧情会话。对话较长时，可打开输入框上方的 **更多 → 压缩上下文**，等待前台和剧情后台处理完成。

## 开启自动压缩

1. 打开 **设置 → Tavern → 上下文压缩**。
2. 选择一种模式：
   - **每 N 轮自动压缩**：填写 1–1000 的整数，例如 20。只统计已完成的不同剧情轮；重写同一轮、工具调用、候选生成、生图及后台任务不增加计数。
   - **上下文达到 X% 自动压缩**：填写 10–95 的整数，例如 80。按前台当前模型窗口与请求上下文的 token 估算判断，不是累计用量或费用。模型容量未知时会提示暂停判断，可改用轮数模式。
3. 点击 **保存压缩设置**。设置对 Tavern 全局生效，各游戏分别计数。启用或修改设置后从当前剧情进度重新计数；成功的手动或自动联合压缩也会重新计数。

两种自动模式互斥。要关闭，选择 **手动压缩（默认）** 并保存；手动压缩按钮始终保留。

## 触发后会发生什么

服务端在安全边界判断：先等待本轮剧情后台结算结束，再联合压缩前台和绑定的剧情后台，随后继续下一轮。已提交的玩家消息会保留，不需要重发；页面无需保持打开。处理期间显示简短状态，不往正文插入通知。

未建立剧情后台会话时跳过后台。生图、手机及卡片编辑等独立任务不跟随压缩。人物卡与固定世界书背景保留，原始 Session 事件和剧情记录不会被删除；模型后续使用压缩摘要继续对话。

部分失败时会显示提示，在 **更多 → 压缩上下文** 中重试，只补失败的一侧。重启后根据持久记录与原生压缩事件核实结果；结果无法确认时提示手动处理，不反复请求压缩。

剧情摘要按卷保存：每次压缩只把新压掉的轮次写成一卷（如「第 31–50 轮剧情摘要」），之前的卷原样保留、不再重新总结，避免早期剧情被一遍遍压缩后越来越模糊。所有卷加起来超过模型窗口的 15% 时，才合并一次成「前情总览」。摘要开头会提示模型：需要原话或细节时，用历史检索工具按关键词或轮次查原文。

压缩可能遗漏细节，不等于无损记忆或备份，重要故事仍建议导出。固定背景本身很长时，压缩历史未必能降到指定比例；页面会提示检查背景长度或使用更大窗口模型。阈值是触发条件，不保证每次请求都不会超出模型窗口。
